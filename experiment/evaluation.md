# Evaluation

> **标准化测评流程。**跑完任何一版说一句「用标准化测评测一下 vN」，照这份执行。
> 这份文档的作用是**防止 cherry-pick**——写死了就不会只报好看的那个指标。

## 一句话触发

```
用标准化测评测一下 v1
```

## 1. 用什么数据

| 用途 | 数据集 | 说明 |
|---|---|---|
| 场景 | Isaac Sim / Isaac Lab 室内场景 | 目标导航的环境 |
| 测试 · 主 | 目标导航 episode 集（主场景集） | 主结果表用这个 |
| 测试 · 副 | 未见场景 episode 集 | 泛化性验证 |

**split 按 scene 分，不按 episode/样本分。**
理由：ObjectNav 要泛化到没见过的 scene，按样本分会泄漏——同一场景的不同 episode 混进测试等于让模型见过这间屋子。

## 2. 报哪些指标

ObjectNav 标准三件套，**全部报，不挑**：

| 指标 | 定义 |
|---|---|
| Success Rate (SR) | 预算内机器人停在目标成功距离阈值内的 episode 占比 |
| Success weighted by Path Length (SPL) | SR ×（最优路径长 / max(实际路径长, 最优路径长)），同时衡量「成功」和「高效」 |
| Distance to Goal (DTG) | 结束时到目标的距离，平均 |

再加一个**分维度拆解**（防平均值掩盖）：按目标类别、按场景分别报 SR。

**必须同时报的参照系**（否则数字没有意义）：

| 参照 | 是什么 |
|---|---|
| baseline | Nav2 + Grounding DINO 基础链（v1） |
| 上界 / Oracle | 真值目标位姿 / 完美 grounding（v2） |
| 随机对照 | 随机导航 / 去掉 grounding 的消融（v3） |

## 3. 必须出的可视化

**每次都要，不管这版结果好不好——效果差的可视化才最有信息量。**

1. 轨迹图（机器人在场景俯视图上的实际路径 + 目标位置）
2. 分目标类别 / 分场景的 SR 柱状图（防平均值掩盖某个维度崩了）
3. **固定 5–10 条失败样例** —— 固定住才能跨版本对比。
   量化指标说好不好，失败样例说为什么

## 4. 输出到哪

```
experiment/<版本名>/
  ├── metrics.json
  ├── trajectory.png
  ├── per_category_sr.png
  └── failure_cases.md
```

跑完把主结果追加到 [results.md](results.md)，**不要覆盖已有行**。

## 不要做的

- ❌ 只报表现最好的那个指标
- ❌ 只报平均不报分维度
- ❌ 效果不好就跳过可视化
- ❌ 每次换一批失败样例（固定住才能对比）
